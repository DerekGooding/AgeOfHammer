# Data overrides

`data/factions/*.json` is generated by `tools/AgeOfHammer.Import` from the AoS Reminders catalog. Don't edit those files by hand, because the next import overwrites them. Put corrections here instead, in a file named `<faction-id>.json`, for example `stormcast-eternals.json`. The importer applies them every time it runs.

```jsonc
{
  // Patch faction-level fields.
  "faction": { "defaultArmy": ["lord-imperatant", "liberators", "liberators"] },

  "warscrolls": {
    "liberators": {
      "verified": true,                                         // you checked it against the source
      "weapons": { "Grandhammer": { "modelsWithWeapon": 1 } },  // keyed by name: patch one weapon
      "abilities": {
        "Stalwart Defenders": {
          "modifiers": [ { "stat": "Control", "value": 3, "condition": "..." } ]
        }
      }
    },
    "some-unit": null                                           // remove a warscroll
  }
}
```

## Merge rules

| What you write | What happens |
|---|---|
| A value | Replaces the generated value. |
| An object | Merges into the generated object. |
| `null` | Removes that field or entry. |
| An array | Replaces the whole array. |
| `weapons`, `abilities` or `spells` as an object keyed by name | Patches that one entry. An entry that doesn't exist yet is added. |
| A warscroll id that doesn't exist yet | Adds a whole new warscroll, so every field must be given. |

## What to review

`data/import-report.md` lists what the importer skipped, the weapons it dropped (profiles that say "See below"), and the **loadout assumptions** it made.

The source data doesn't say which models in a unit carry which weapon. So when a multi-model unit has several weapons of the same type, the importer guesses: every model uses the weakest one, and the others go to 1 model in 5. Each guess is also recorded in that warscroll's `notes`. Correct it here with `modelsWithWeapon`.
